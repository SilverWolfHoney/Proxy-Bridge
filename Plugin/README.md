# 本地代理网关 · 浏览器插件

一个 Chrome / Edge 的 Manifest V3 扩展。它只做一件事：**把浏览器的 HTTP/HTTPS 代理指向本机的桌面应用**（`127.0.0.1:<本地端口>`），由桌面应用负责连接真正的远程代理服务器。

> **安全声明**
> 本插件**不保存、不接收、也不包含任何远程代理服务器的地址、端口、用户名或密码**。
> 插件内部唯一出现的网络地址是本机回环地址 `127.0.0.1`。真实账号密码全部由桌面应用持有和管理。

---

## 一、目录结构

```
Plugin/
├── manifest.json          # MV3 清单：权限、后台 Service Worker、弹窗、设置页
├── README.md              # 本文件
└── src/
    ├── shared.js          # 共享常量与工具（默认配置、存储键、健康探测）
    ├── background.js      # Service Worker：设置/清除代理、探测桌面应用、更新徽章
    ├── popup.html         # 工具栏弹窗结构
    ├── popup.css          # 工具栏弹窗样式
    ├── popup.js           # 工具栏弹窗逻辑（开关、状态灯、打开设置）
    ├── options.html       # 设置页结构
    ├── options.css        # 设置页样式
    └── options.js         # 设置页逻辑（端口、绕过列表）
```

没有构建步骤、没有第三方依赖、没有 `node_modules`：全部是原生 HTML / CSS / JavaScript（ES Module）。

## 二、如何加载

1. 打开浏览器，地址栏输入 `chrome://extensions`（Edge 为 `edge://extensions`）并回车。
2. 打开右上角的 **开发者模式**。
3. 点击 **加载已解压的扩展程序**。
4. 在弹出的目录选择框里选中本目录（即包含 `manifest.json` 的 `Plugin` 目录），确认。
5. 扩展列表中出现「本地代理网关」，把它固定到工具栏即可。

修改代码后，回到扩展页面点击本插件卡片上的 **刷新** 按钮即可生效；修改 `background.js` 后建议同时重新加载扩展。

## 三、如何使用

### 1. 先启动桌面应用

桌面应用负责真正连接远程代理服务器，并监听 `127.0.0.1:<本地端口>`（默认 `7890`）。
**必须先在桌面应用里开启本地监听**，插件才能把流量交给它。

### 2. 打开弹窗，检查状态

点击工具栏上的插件图标：

- **桌面应用**：显示「运行中」表示已成功探测到桌面应用；显示「未运行」表示探测失败（此时插件不会接管代理）。
- **本地代理地址**：显示 `127.0.0.1:<本地端口>`。
- **代理状态**：是否已真正接管浏览器代理。
- **最近检测**：最近一次探测的时间。

如果桌面应用没启动，弹窗、设置页和扩展徽章都会给出明确提示。

### 3. 打开开关

点击弹窗顶部的大开关：

- **开启**：浏览器代理被设置为 `127.0.0.1:<本地端口>`，徽章显示绿色的 `ON`。
- **关闭**：清除代理设置，浏览器恢复直连，徽章不显示文字。

开关切换后立即生效，无需重启浏览器。

### 4. 修改本地端口与绕过列表

点击弹窗里的 **打开设置**，或右键插件图标选择 **选项**：

- **本地端口**：必须和桌面应用里的本地监听端口一致，范围 `1–65535`，默认 `7890`。
- **绕过列表**：每行一条，命中的地址不经过代理（默认 `localhost`、`127.0.0.1`）。

修改后点击 **保存并立即生效**。

## 四、工作原理

```
浏览器 ──► 本插件（chrome.proxy 固定代理）
              │
              ▼
        127.0.0.1:<本地端口>   ◄── 桌面应用在本机监听
              │
              ▼
        远程代理服务器（地址与账号密码只有桌面应用知道）
```

具体行为：

1. **开启代理**：调用 `chrome.proxy.settings.set`，写入

   ```js
   {
     mode: 'fixed_servers',
     rules: {
       singleProxy: { scheme: 'http', host: '127.0.0.1', port: <本地端口> },
       bypassList: [...]
     }
   }
   ```

   HTTP 与 HTTPS 流量都会走这个本地端口。

2. **关闭代理**：调用 `chrome.proxy.settings.clear`，恢复浏览器直连。

3. **健康探测**：插件周期性请求

   ```
   http://127.0.0.1:<本地端口>/__proxybridge__/health
   ```

   期望返回 `{"app":"proxy-bridge","ok":true,"version":"..."}`。请求带 1.5 秒超时（`AbortController`），
   不会卡住界面。探测结果写入 `chrome.storage.session`，弹窗和设置页直接读取。

   探测同时校验响应体里的 `app` 字段，避免把本机其它恰好占用同一端口的 HTTP 服务误判成桌面应用。

4. **自动降级（防断网保护）**：如果开关是开启状态，但探测不到桌面应用，插件会**立即清除代理设置、恢复直连**，
   并把状态标记为「已降级」，徽章显示橙色的 `!`。这样即使桌面应用崩溃或退出，浏览器也不会彻底断网。
   桌面应用恢复运行后，下一次探测成功即自动重新接管代理。

5. **探测频率**：Service Worker 存活期间每 3 秒探测一次；同时注册了 30 秒周期的 `chrome.alarms` 作为兜底，
   保证 Service Worker 被浏览器回收后仍能定期唤醒检查。

6. **配置持久化**：配置保存在 `chrome.storage.local`（`{ enabled, port, bypassList }`）。
   浏览器启动、扩展安装/更新、配置变更时都会自动重新读取并应用。
   MV3 的 Service Worker 会被随时休眠，因此代码中不依赖任何模块级持久状态，所有状态都从 `chrome.storage` 读取。

## 五、权限说明

| 权限 | 用途 |
| --- | --- |
| `proxy` | 设置/清除浏览器代理（插件的核心功能） |
| `storage` | 保存配置（`local`）与运行时状态（`session`） |
| `alarms` | Service Worker 休眠后的兜底健康探测 |
| `http://127.0.0.1/*`、`http://localhost/*` | 访问本机健康检查端点 |

插件**没有**申请 `<all_urls>`，也**不会**读取、修改任何网页内容，没有内容脚本。

## 六、故障排查

### 弹窗提示「桌面应用未运行」

- 确认桌面应用已经启动，并且已经在里面开启本地监听。
- 确认桌面应用监听的端口与插件设置页里的**本地端口**完全一致。
- 在浏览器地址栏直接访问 `http://127.0.0.1:<本地端口>/__proxybridge__/health`，
  正常情况下会看到类似 `{"app":"proxy-bridge","ok":true,"version":"0.1.0"}` 的 JSON。
  - 打不开：问题在桌面应用侧（没启动 / 端口不对 / 防火墙拦截了本机回环地址）。
  - 能打开但内容不是上面这种 JSON：该端口被别的程序占用了，请换一个端口，或在桌面应用里改成别的端口。
- 点击弹窗的 **重新检测** 或设置页的 **重新检测桌面应用** 立即重试。

### 开关显示开启，但状态是「已降级」

这是防断网保护：插件探测不到桌面应用，于是自动切回直连。启动桌面应用后，等几秒或点 **重新检测** 即可恢复。

### 提示「端口已被占用，但响应不是本插件配套的桌面应用」

本机该端口上跑着其它 HTTP 服务。请在桌面应用里换一个本地端口，并在插件设置页同步修改。

### 提示「代理设置已被其他扩展接管」

Chrome 同一时间只允许一个扩展控制代理设置。请先关闭其它代理类扩展（或它们的代理接管功能），再重新开启本插件。

### 提示「设置代理失败」

- 到 `chrome://extensions` 确认本插件已启用、没有报错。
- 点击本插件卡片上的 **刷新** 重新加载。
- 如果仍失败，卸载后重新「加载已解压的扩展程序」。

### 开启代理后网页打不开或提示证书错误

流量已经交给桌面应用了，问题多半出在桌面应用到远程代理服务器这一段：

- 桌面应用里配置的远程服务器信息是否正确、是否已连接成功；
- 若桌面应用对 HTTPS 做中间人解密，需要在系统或浏览器中信任它生成的根证书；
- 也可以先关掉本插件开关，确认浏览器直连是正常的，以便区分是哪一段出的问题。

### 想临时恢复直连

关闭弹窗里的大开关即可；也可以在 `chrome://extensions` 里直接停用本插件。
必要时可在系统代理设置中确认没有残留的代理配置。

## 七、隐私说明

- 插件只申请了 `proxy`、`storage`、`alarms` 三项权限，以及对本机回环地址的访问权限。
- 插件不读取网页内容、不注入脚本、不收集任何数据、不向任何远程地址发送请求。
- 插件中唯一的对外网络请求是访问 `http://127.0.0.1:<本地端口>/__proxybridge__/health` 做存活探测。
- 插件存储的内容只有三项：开关状态、本地端口号、绕过列表。**不包含任何凭据信息。**

示例中出现的 `example.com`、`*.internal` 等均为文档占位符，不代表任何真实服务器。
