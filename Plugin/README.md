# 代理快速切换（浏览器扩展）

一个 Chrome / Edge 的 Manifest V3 扩展：把你自己填写的远程代理服务器配置应用到浏览器，支持一键开关、账号密码认证、域名绕过。

> **本扩展是独立的代理客户端。**
> 它自己连接代理服务器，不依赖、不探测、也不需要任何桌面应用或其他本机程序。
> 同理，本扩展与同仓库的 `Application/` 桌面应用没有任何关联——两者是两个平级的客户端，各自连接同一个代理服务器即可。

---

## 一、安装

1. 打开 Chrome 的 `chrome://extensions`（Edge 为 `edge://extensions`）。
2. 打开右上角的 **开发者模式**。
3. 点击 **加载已解压的扩展程序**，选择本目录（`Plugin/`）。
4. 在扩展卡片上点击 **详情 → 扩展程序选项**（或右键图标选 **选项**）打开设置页。

---

## 二、配置

设置页需要填写四项内容：

| 字段 | 说明 |
| --- | --- |
| **协议** | `HTTP` / `HTTPS` / `SOCKS5`，按服务商提供的选择 |
| **服务器地址** | 域名或 IP，不要带 `http://` 前缀 |
| **端口** | `1–65535` |
| **认证** | 服务器要求用户名密码时打开开关并填写 |

填完点 **保存**，浏览器代理即刻生效。

> 同仓库的 `Application/` 桌面应用与本扩展**配置互不相通**，同一台服务器的信息需要各填一次。
> 本扩展完全可以单独使用。

---

## 三、使用

点击工具栏图标打开弹窗：

- **连接状态卡**（最显眼的那一块）：直接告诉你现在到底能不能上网
- **大开关**：开启后浏览器流量走你配置的代理服务器；关闭则恢复直连
- **代理服务器 / 认证 / 出口 IP / 最近检测**：当前生效的配置与结果
- **重新检测**：立刻重新验证一次（连不上时用它手动重试）

### 连接状态

只看「代理已开启」是不够的——那只说明配置写进去了，不代表真的能出网。
所以开启后会**真的探测一次**，把结果如实显示出来：

| 状态 | 含义 |
| --- | --- |
| **正在连接…** | 刚开启，正在验证 |
| **已连接** | 经代理能正常出网（同时显示出口 IP） |
| **连不上服务器** | 配置已生效，但经它出不去，附具体原因 |
| **未开启** | 开关是关的 |

**探测节奏**：开启时立刻测一次；失败后按 **30 / 60 / 90 / 120 秒**重试，
最坏情况下共测 5 次、累计正好 5 分钟，之后停止自动重试（不再无谓消耗流量），
等你手动点「重新检测」。连通之后每 **60 秒**再确认一次，用以及早发现掉线。

探测失败**不会**把代理切回直连——浏览器仍然按你配的走，只是明确告诉你它不通。
探测仅在开关开启时进行。

扩展图标上的徽章：绿色 `ON` 表示已连接，橙色 `!` 表示连不上服务器，红色 `!` 表示代理设置本身失败。

### 域名绕过

设置页的 **不经过代理的地址** 每行一条，命中的地址浏览器会直接连接：

```
localhost
127.0.0.1
*.internal
```

支持通配符写法；留空表示全部走代理。

## 四、工作原理

```
浏览器 ──► 本扩展（chrome.proxy 设置 fixed_servers）
              │
              ▼
        你填写的代理服务器 ──► 目标网站
```

1. **开启代理**：调用 `chrome.proxy.settings.set`，把 `singleProxy` 指向你填写的
   `协议://地址:端口`，并带上绕过列表。

2. **关闭代理**：调用 `chrome.proxy.settings.clear`，恢复浏览器直连。

3. **代理认证**：HTTP/HTTPS 代理返回 `407 Proxy Authentication Required` 时，
   扩展通过 `chrome.webRequest.onAuthRequired` **自动提交你保存的账号密码**，
   你不会看到浏览器弹出的登录框。

   这个监听器只处理**代理服务器**发起的认证（`details.isProxy === true`）；
   网站自身的登录框（401）不受影响，正常显示。

4. **配置不完整时不接管**：如果开关是开的但服务器地址或端口没填，扩展会保持直连，
   而不会把浏览器指到一个空地址上导致断网。

5. **连通性探测**：开启后经代理访问一个轻量端点（`api.ipify.org`、`icanhazip.com`），
   以此确认「真的能出网」并顺便取回出口 IP。失败则按 30/60/90/120 秒重试，
   累计 5 分钟后停止；成功则每 60 秒再确认一次。开关关闭时完全不探测。

6. **定期校准**：每 5 分钟通过 `chrome.alarms` 重新应用一次配置，
   防止 Service Worker 被回收或代理设置被外部改动后长期不一致。

## 五、权限说明

| 权限 | 用途 |
| --- | --- |
| `proxy` | 设置/清除浏览器代理，这是扩展的核心功能 |
| `storage` | 保存你填写的服务器配置与连接状态 |
| `webRequest` + `webRequestAuthProvider` | 自动应答代理服务器的认证请求 |
| `alarms` | 定期校准代理设置 |
| `<all_urls>` | `onAuthRequired` 需要覆盖所有请求才能拦截到代理认证 |

扩展不注入脚本、不读取网页内容、不修改页面。唯一的对外请求就是上面那条探测
（仅在开关开启时发出）。

## 六、已知限制

### SOCKS5 的认证无法自动完成

Chromium **不提供**向 SOCKS5 代理注入凭据的接口（认证发生在协议层，不在 HTTP 层）。
因此使用 **SOCKS5 + 账号密码** 时，浏览器会弹出原生的登录框要求输入。

建议：

- 优先使用 **HTTP 代理**，认证可以完全自动化；
- 或让服务商提供一个免认证的 IP 白名单方式；
- 如果必须用 SOCKS5 + 认证，可以在 `chrome://settings` 的代理设置里让 Chrome 记住密码。

### 同一时间只能有一个扩展控制代理

Chrome 只允许一个扩展接管 `chrome.proxy`。如果同时装了其它代理类扩展，
两者会互相覆盖，弹窗里会提示「代理设置已被其他扩展接管」。

### 企业策略可能锁定代理

如果设备由公司统一管控，`chrome.proxy` 可能被策略覆盖，扩展的设置不会生效。

## 七、故障排查

### 开启后网页打不开

按顺序确认：

1. 设置页里的地址、端口、协议是否与服务商提供的一致。
2. 认证开关是否与服务器要求匹配（不需要认证却开了，或需要认证却没开）。
3. 在弹窗里点 **重新检测**，看连接状态卡与提示条说了什么。
4. 打开 `chrome://net-export/` 抓一次网络日志，可以看到连接失败的具体原因。

### 弹窗提示「代理设置已被其他扩展接管」

到 `chrome://extensions` 关闭其它代理类扩展，或关闭它们的代理控制功能。

### 一直弹出代理登录框

说明你在用 SOCKS5 + 认证（见上面「已知限制」），或者填写的账号密码不正确。
HTTP 代理的认证由扩展自动完成，正常情况下不应出现弹窗。

### 设置保存了但没生效

- 到 `chrome://extensions` 点本扩展卡片上的 **刷新** 重新加载。
- 确认扩展图标徽章不是红色 `!`。
- 检查是否有企业策略在强制代理设置。

---

## 八、隐私

- 服务器地址与账号密码**只保存在本机**的 `chrome.storage.local` 中，不会上传到任何地方。
- 扩展唯一的对外请求是**连通性探测**：仅在开关开启时，经你自己配置的代理访问
  `https://api.ipify.org` 或 `https://icanhazip.com`，用来看代理是否真的能用、出口 IP 是多少。
  除此之外不与任何服务器通信；探测请求也只会发往上面这两个公开的 IP 查询服务。
- 不想让它探测就把开关关掉——关闭状态下完全不发请求。
- 密码可以选择不保存：设置页关闭「把密码保存在浏览器扩展存储中」后，
  密码只留在内存里，浏览器重启后需要重新输入。
- 清空配置会连同账号密码一起从扩展存储中删除。

## 九、文件结构

```
Plugin/
├── manifest.json          # MV3 清单：权限、Service Worker、弹窗、设置页
├── README.md
└── src/
    ├── shared.js          # 共享常量与工具：默认配置、规范化、chrome.proxy 参数构建
    ├── background.js      # Service Worker：应用代理、代理认证应答、徽章
    ├── popup.html         # 弹窗结构
    ├── popup.css          # 弹窗样式
    ├── popup.js           # 弹窗逻辑（开关、连接状态、出口 IP）
    ├── options.html       # 设置页结构
    ├── options.css        # 设置页样式
    └── options.js         # 设置页逻辑（服务器、认证、绕过列表）
```

示例中出现的 `proxy.example.com`、`203.0.113.10`、`*.internal` 等均为文档占位符，
不代表任何真实服务器。
