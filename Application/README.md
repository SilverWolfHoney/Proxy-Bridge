# Proxy Bridge

一个把浏览器流量安全地交给远程代理服务器的桌面应用 + 浏览器插件组合。

- **Application/** —— Electron 桌面应用。持有你的代理服务器地址和账号密码，在本机开一个代理端口，按规则把流量转发出去。
- **Plugin/** —— Chrome / Edge 插件（Manifest V3）。只做一件事：把浏览器的代理指向本机那个端口。它**不保存任何服务器凭据**。

> 本仓库不包含、也不预置任何真实的代理服务器地址、端口、账号或密码。所有服务器信息都需要你在应用界面里自己填写，并只保存在本机。

---

## 为什么这么设计

直接把账号密码交给浏览器插件，意味着凭据会散落在浏览器配置里，换服务器还得重新改插件。

这里的做法是：

```
浏览器 ──► 插件（只知道 127.0.0.1:7890） ──► 桌面应用（持有凭据、执行分流）
                                                  │
                                        ┌─────────┴─────────┐
                                        ▼                   ▼
                                   直连目标            远程代理服务器
```

好处：

1. **凭据只有一份**，存在应用里并用系统加密（Windows DPAPI）保护，插件和浏览器配置里都没有。
2. **换服务器不用碰插件**，改应用里的配置即可。
3. **可以做分流**，内网、网银之类被判为直连的流量不会绕道远程服务器。
4. **有日志和流量统计**，能看清每个连接走了哪条路、为什么失败。

## 快速开始

### 1. 启动应用

```powershell
cd Application
npm install
npm start          # 构建并启动
```

开发模式（界面改动热更新，一条命令同时拉起 Vite 与 Electron）：

```powershell
npm run dev
```

其它常用命令：

```powershell
npm run typecheck   # 类型检查（主进程 + 界面）
npm test            # 单元测试 + 本地网关端到端测试（全部走本机模拟服务）
npm run build       # 只构建，不启动
```

### 2. 填写你的服务器信息

打开应用 → **代理服务器** 页 → 填写协议、地址、端口、用户名、密码 → 点 **测试连接**。

测试成功时会显示握手耗时和**出口 IP** —— 这个 IP 就是目标网站看到的来源地址，可以用它确认流量确实从代理出去了。

### 3. 启动网关

点右上角 **启动网关**。默认监听 `127.0.0.1:7890`，只监听本机回环，局域网内其他设备访问不到。

### 4. 安装浏览器插件

1. Chrome / Edge 打开 `chrome://extensions`（Edge 是 `edge://extensions`）
2. 打开右上角 **开发者模式**
3. 点 **加载已解压的扩展程序**，选择 `Plugin/` 目录（应用「插件 / 关于」页有按钮可以直接打开这个目录）
4. 在插件设置里确认**本地端口**（默认 `7890`，一般不用改——插件会自动探测应用实际监听的端口并跟随过去）
5. 点击插件图标，打开开关

## 三种使用方式，按需选择

| 方式 | 作用范围 | 适合场景 |
| --- | --- | --- |
| **浏览器插件** | 只影响浏览器 | 日常使用，随时开关，不动系统设置 |
| **系统代理开关** | 所有读取系统代理的程序 | 需要让其他软件也走代理 |
| **直接指向端口** | 单个程序 | 支持自定义代理的软件（如 curl、Git、Telegram） |

系统代理开关在应用「代理服务器」页底部。开启后应用会写入 Windows 系统代理设置，**关闭开关或退出应用时自动还原成你原来的设置**，不会留下残余。

命令行程序可以直接用同一个端口：

```powershell
curl.exe -x http://127.0.0.1:7890 https://api.ipify.org
curl.exe -x socks5h://127.0.0.1:7890 https://api.ipify.org   # 同一端口也支持 SOCKS5
```

## 端口自动同步

应用在 `127.0.0.1` 上监听，插件只认识这一个本地端口。**这个端口不需要你在两处各填一遍**：

- 应用的健康检查会报出自己真实的监听端口。
- 插件每次探测时，如果发现应用跑在别的端口上，会**自动把配置改过去**，并在弹窗里标出「已自动跟随应用」。
- 你在应用里改了网关端口 → 最迟几秒内插件就跟上了，浏览器不会断流。

插件会按顺序尝试这些端口（配置里的端口永远优先）：

```
配置的端口 → 7890 → 7891 → 7892 → 7893 → 8080 → 8888 → 1080 → 10808 → 20171 → 7897
```

所以网关端口如果设成这些之外的数字（例如 `34567`），插件扫不到，需要你在插件设置页手动填一次——填过之后它就是首选项，会优先被尝试。

同一台机器上连接被拒绝是立即返回的，扫一遍候选端口几乎不花时间，不会拖慢探测。

## 分流规则

在 **分流规则** 页配置，修改后立即生效，无需重启。

匹配优先级：**强制走代理** > **强制直连** > 默认走代理。

| 写法 | 含义 |
| --- | --- |
| `example.com` | 匹配 example.com 及其所有子域名 |
| `*.example.com` | 同上，显式通配写法 |
| `192.168.*` | 前缀通配，适合 IP 段 |
| `example.com:8080` | 限定端口，不写端口表示任意端口 |
| `# 注释` | 以 `#` 或 `//` 开头的行被忽略 |

「强制走代理」列表**留空**时，所有流量都走代理（黑名单模式）；
一旦填了内容，就变成**白名单模式** —— 只有命中的目标走代理，其余全部直连。

## 常见问题

**测试连接提示「认证失败（407）」或「SOCKS5 认证失败」**

用户名或密码不正确。特别注意**大小写** —— 很多服务商的用户名里混有大写字母 `I`、小写 `l` 和数字 `1`，很容易看错。密码同理。

**测试连接提示「连接超时」**

本机网络到该服务器不通。确认地址和端口没填错，以及本机防火墙/公司网络没有拦截这个端口。

**网关启动失败：「端口已被占用」**

换一个端口，或者用 `netstat -ano | findstr :7890` 找到占用它的进程。

**浏览器打不开网页了**

插件开着但应用没启动。插件探测不到本机应用时会自动降级为直连，正常情况下不会断网；如果仍然异常，手动关掉插件开关即可。

**系统代理开关点了没反应**

需要先启动网关，开关才有意义。另外部分企业管控的电脑会锁死代理设置，这种情况只能用浏览器插件。

## 目录结构

```
Application/
  src/
    core/            与界面无关的核心逻辑（可在纯 Node 下测试）
      bridge.ts        本地网关：HTTP 代理 + SOCKS5 服务端 + 流量统计
      connector.ts     与远程代理服务器建立隧道（http / https / socks5）
      rules.ts         分流规则匹配
      tester.ts        连通性测试与出口 IP 查询
    main/            Electron 主进程
      main.ts          窗口、IPC、生命周期
      store.ts         配置持久化与凭据加密
      systemProxy.ts   Windows 系统代理接管与还原
      preload.ts       暴露给界面的安全 API
    renderer/        React 界面
    shared/          主进程与界面共用的类型定义
Plugin/              Chrome / Edge 扩展（Manifest V3）
```

## 安全说明

- 配置文件位于 `%APPDATA%/proxy-bridge/config.json`，其中密码字段用 Windows DPAPI 加密后存储。
- 若当前系统不支持加密，会退化为**带明确标记**的明文存储并在配置里标注，不会静默降级。
- 网关只监听 `127.0.0.1`；如果改成 `0.0.0.0`，局域网内任何人都能免费使用你的代理，请勿随意修改。
- 连接日志只保留在内存中（最多 300 条），退出即清空，且从不记录凭据。

---

## 卸载

1. 在应用里关闭「系统代理」开关（或直接退出，应用会自动还原）。
2. 删除 `%APPDATA%/proxy-bridge/` 目录，彻底清除配置与凭据。
3. 浏览器里移除插件。
