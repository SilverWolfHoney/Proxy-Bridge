# Proxy Bridge（桌面应用）

Windows 桌面应用：填一次代理服务器信息，打开一个开关，**整台电脑**的流量就走代理。

基于 Electron + React + TypeScript。

---

## 安装与运行

```powershell
cd Application
npm install
npm start
```

首次运行会构建再启动，大约几秒。之后的日常使用：

```powershell
npm start
```

## 界面

只有一个页面。

### 总开关

界面顶部那个大开关，是整个应用的核心。打开它时会自动按顺序完成三件事：

1. **校验服务器**：先测试代理服务器是否可用，连不上就直接拒绝，并告诉你原因
2. **启动本机转发端口**：默认 `127.0.0.1:7890`
3. **接管 Windows 系统代理**：把系统代理指向上面那个端口

关闭开关时反向执行：还原系统代理 → 停止本机端口。

> **为什么要本机端口？**
> Windows 的系统代理设置只能填一个本机地址，不允许直接填"远程服务器 + 账号密码"。
> 所以任何全局代理工具内部都必须有这么一个本机端口。它是实现方式，不需要你操心。
>
> 打开全局代理期间，你也可以手动把某个程序的代理指向 `127.0.0.1:7890`
> （同时支持 HTTP 和 SOCKS5 两种协议），不必依赖系统代理。

### 代理服务器

| 字段 | 说明 |
| --- | --- |
| **协议** | 默认 **自动识别**；也可以手动指定 `HTTP 代理` / `HTTPS 代理` / `SOCKS5` |
| **服务器地址** | 域名或 IP，不要带 `http://` 前缀 |
| **端口** | `1–65535` |
| **用户名密码** | 服务器要求认证时打开开关并填写 |

**不确定该选哪个协议时，保持「自动识别」即可。** 点一次 **测试连接**，应用会依次尝试
HTTP → SOCKS5 → HTTPS，把能用的那一种**记下来**（协议旁边会显示「已识别：SOCKS5」）。
之后就一直用它，不再重复尝试；下次开全局代理也直接用这个结果。

换了服务器地址、端口、用户名或协议，识别结果会自动作废并重新判断。

**测试连接** 会真实建立一次到服务器（再经它连出去）的隧道：

- 成功时显示握手耗时和**出口 IP** —— 那就是目标网站看到的来源地址
- 失败时给出具体原因，而不仅仅是"失败"：

| 提示 | 含义 |
| --- | --- |
| 认证失败（407）/ SOCKS5 认证失败 | 用户名或密码不对 |
| 连接超时 | 本机到该服务器不通 |
| 连接被拒绝 | 端口填错了 |
| 域名解析失败 | 服务器地址拼错了 |

自动识别失败时，界面会把**每种协议各自的原因**列出来（例如「HTTP 代理：认证失败 ／
SOCKS5：连接超时」），不必自己反复试。

### 高级设置（默认折叠）

| 项 | 说明 |
| --- | --- |
| **本机端口** | 全局代理的工作端口，默认 `7890`。被别的软件占用时改这里 |
| **开机自动开启** | 勾选后，下次启动应用时自动恢复全局代理 |
| **不走代理的地址** | 每行一条，命中的目标直连。适合内网、公司系统 |

「不走代理的地址」支持的写法：

| 写法 | 含义 |
| --- | --- |
| `example.com` | 匹配 example.com 及其所有子域名 |
| `*.example.com` | 同上，显式通配写法 |
| `192.168.*` | 前缀通配，适合 IP 段 |
| `example.com:8080` | 限定端口，不写端口表示任意端口 |
| `# 注释` | 以 `#` 开头的行会被忽略 |

留空表示**所有**流量都走代理。

## 配置与凭据存放位置

```
%APPDATA%\proxy-bridge\config.json
```

- 密码字段用 **Windows DPAPI** 加密后存储（密文前缀 `enc:`）
- 若当前系统不支持加密，会退化为**带明确标记**的明文存储（前缀 `plain:`），不会静默降级
- 该文件**不在仓库目录内**，不会被提交到版本库
- 卸载时删掉整个 `%APPDATA%\proxy-bridge\` 目录即可彻底清除

## 常见问题

**打开开关又自己弹回来了**

开关会先校验服务器，连不上就拒绝开启——这是有意的，否则开了等于让整台电脑断网。
点 **测试连接** 看具体原因。

**提示本机端口被占用**

进高级设置把「本机端口」换成别的（例如 `7891`）。用
`netstat -ano | findstr :7890` 可以找到占用它的进程。

**开了全局代理后网页打不开**

先点 **测试连接** 复查服务器。如果测试通过但网页仍打不开，可能是代理服务器对某些站点不可用。
关掉开关即可立刻恢复直连。

**系统代理开关没反应**

部分企业管控的电脑会锁死代理设置，这种情况系统代理无法生效，
但本机端口（`127.0.0.1:7890`）仍然可用——手动把程序的代理指过去即可。

**退出应用后网络异常**

正常退出会自动还原系统代理。如果应用被强制结束，重新启动一次应用即可自动清理残留。

## 目录结构

```
Application/
  src/
    core/            与界面无关的核心逻辑（可在纯 Node 下测试）
      bridge.ts        本机转发端口：HTTP 代理 + SOCKS5 服务端
      connector.ts     与远程代理服务器建立隧道（http / https / socks5）
      rules.ts         直连例外匹配
      tester.ts        连通性测试与出口 IP 查询
    main/            Electron 主进程
      main.ts          窗口、IPC、全局代理开关的状态机、生命周期
      store.ts         配置持久化与凭据加密
      systemProxy.ts   Windows 系统代理接管与还原
      preload.ts       暴露给界面的安全 API
    renderer/        React 界面
      components/HomePage.tsx   唯一的页面
    shared/          主进程与界面共用的类型定义
  tests/             单元测试与端到端测试
  scripts/dev.mjs    开发模式启动器
```

## 开发

```powershell
npm run dev         # 开发模式：Vite + Electron，界面改动热更新
npm run typecheck   # 类型检查（主进程 + 界面）
npm test            # 全部测试
npm run build       # 只构建
npm run clean       # 清掉构建产物
```

**别用 `npx electron .`** —— 那会被当成开发模式去连一个没启动的开发服务器，结果是空白窗口。
用 `npm start`（构建后启动）或 `npm run dev`（开发模式）。

### 测试内容

测试全部使用本机临时服务，不接触任何外部服务器、不联网：

- 直连例外匹配：域名、通配符、端口限定的各种写法与优先级
- HTTP 与 SOCKS5 上游转发：认证头注入、认证失败处理、失败统计
- 字节级时序：隧道建立瞬间，目标首包与握手应答落在同一个 TCP 段时，不丢字节也不串位
- 健康检查端点：用于外部探测应用是否在运行
