# Proxy Bridge（桌面应用）

一个把本机流量交给远程代理服务器的桌面应用。

- **Application/**（本目录）—— Electron 桌面应用。持有你的代理服务器地址和账号密码，在本机开一个代理端口，按规则把流量转发出去，还能接管 Windows 系统代理。
- **Plugin/** —— Chrome / Edge 插件（Manifest V3）。它是一个**平级的独立客户端**：自己连接代理服务器，不依赖本应用运行。

**两者互不依赖**，填同一台服务器即可，用哪个都行：

```
浏览器插件 ──┐
             ├──► 你的远程代理服务器 ──► 目标网站
本应用     ──┘
```

> 本仓库不包含、也不预置任何真实的代理服务器地址、端口、账号或密码。所有服务器信息都需要你自己填写，并只保存在本机。

---

## 为什么需要这个应用

只用浏览器插件也能上网，但插件管不到浏览器之外的东西，也做不了应用级的分流。本应用补上这些：

1. **管到浏览器之外**：开一个本机代理端口，curl、Git、其它软件都能用；还能一键接管 Windows 系统代理。
2. **能做分流**：内网、网银之类被判为直连的流量不会绕道远程服务器。
3. **有日志和流量统计**：每个连接走了哪条路、为什么失败，看得一清二楚。
4. **凭据用系统加密保护**：密码以 Windows DPAPI 加密存储，而不是明文躺在配置文件里。

插件那边的账号密码由浏览器扩展自己保管，与本应用无关——两边是各自独立的配置。

## 快速开始

### 1. 启动应用

```powershell
cd Application
npm install
npm start          # 构建并启动
```

开发模式（界面改动热更新，一条命令同时拉起 Vite 与 Electron）：

```powershell
npm run dev
```

其它常用命令：

```powershell
npm run typecheck   # 类型检查（主进程 + 界面）
npm test            # 单元测试 + 本地网关端到端测试（全部走本机模拟服务）
npm run build       # 只构建，不启动
```

### 2. 填写你的服务器信息

打开应用 → **代理服务器** 栏 → 填写协议、地址、端口、用户名、密码 → 点 **测试连接**。

测试成功时会显示握手耗时和**出口 IP** —— 这个 IP 就是目标网站看到的来源地址，可以用它确认流量确实从代理出去了。

### 3. 打开全局代理开关

点界面上那个大开关。它会自动按顺序做三件事：

1. **先校验服务器可用**（避免开完上不了网）
2. 启动本机转发端口（默认 `127.0.0.1:7890`，只监听本机回环）
3. 接管 Windows 系统代理

关掉开关时反向执行：还原系统代理 → 停止本机端口。**退出应用时也会自动还原。**

### 4. 想让浏览器单独走代理？

仓库里的 `Plugin/` 是一个**独立的浏览器扩展**，它自己直连代理服务器，与本应用无关、也不需要本应用运行。
如果只想让浏览器走代理，装它就行，详细说明见 `../Plugin/README.md`。

## 三种用法

| 用法 | 作用范围 | 怎么用 |
| --- | --- | --- |
| **全局代理开关** | 所有读取系统代理的程序 | 界面上的大开关 |
| **直接指向本机端口** | 单个程序 | 支持自定义代理的软件（curl、Git、Telegram 等）填 `127.0.0.1:7890` |
| **浏览器插件** | 只影响浏览器 | 独立客户端，不必启动本应用，见 `Plugin/README.md` |

开关开启期间，命令行程序可以直接用本机端口：

```powershell
curl.exe -x http://127.0.0.1:7890 https://api.ipify.org
curl.exe -x socks5h://127.0.0.1:7890 https://api.ipify.org   # 同一端口也支持 SOCKS5
```

## 直连例外

默认**所有流量都走代理**。需要让某些地址直连（内网、公司系统等）时，
展开界面上的 **高级设置** → **不走代理的地址**，每行填一条。

| 写法 | 含义 |
| --- | --- |
| `example.com` | 匹配 example.com 及其所有子域名 |
| `*.example.com` | 同上，显式通配写法 |
| `192.168.*` | 前缀通配，适合 IP 段 |
| `example.com:8080` | 限定端口，不写端口表示任意端口 |
| `# 注释` | 以 `#` 或 `//` 开头的行被忽略 |

「强制走代理」列表**留空**时，所有流量都走代理（黑名单模式）；
一旦填了内容，就变成**白名单模式** —— 只有命中的目标走代理，其余全部直连。

## 常见问题

**测试连接提示「认证失败（407）」或「SOCKS5 认证失败」**

用户名或密码不正确。特别注意**大小写** —— 很多服务商的用户名里混有大写字母 `I`、小写 `l` 和数字 `1`，很容易看错。密码同理。

**测试连接提示「连接超时」**

本机网络到该服务器不通。确认地址和端口没填错，以及本机防火墙/公司网络没有拦截这个端口。

**提示本机端口被占用**

进 **高级设置** 把「本机端口」换成别的（例如 7891）。用
`netstat -ano | findstr :7890` 可以找到占用它的进程。

**打开开关又自己弹回来了 / 提示服务器连不上**

开关会先校验服务器，连不上就拒绝开启——这是有意的，否则开了等于让整台电脑断网。
先点 **测试连接** 看具体原因。

**开了全局代理后网页打不开**

点 **测试连接** 复查服务器；如果测试通过但网页仍打不开，可能是代理服务器本身对
某些站点不可用。关掉开关即可立刻恢复直连（系统代理会被还原）。

**系统代理开关点了没反应**

部分企业管控的电脑会锁死代理设置，这种情况只能用浏览器插件（`Plugin/`）。

## 目录结构

```
Application/
  src/
    core/            与界面无关的核心逻辑（可在纯 Node 下测试）
      bridge.ts        本地网关：HTTP 代理 + SOCKS5 服务端 + 流量统计
      connector.ts     与远程代理服务器建立隧道（http / https / socks5）
      rules.ts         直连例外匹配
      tester.ts        连通性测试与出口 IP 查询
    main/            Electron 主进程
      main.ts          窗口、IPC、生命周期
      store.ts         配置持久化与凭据加密
      systemProxy.ts   Windows 系统代理接管与还原
      preload.ts       暴露给界面的安全 API
    renderer/        React 界面
    shared/          主进程与界面共用的类型定义
```

`Plugin/` 是另一个独立项目（浏览器扩展），见 `../Plugin/README.md`。

## 安全说明

- 配置文件位于 `%APPDATA%/proxy-bridge/config.json`，其中密码字段用 Windows DPAPI 加密后存储。
- 若当前系统不支持加密，会退化为**带明确标记**的明文存储并在配置里标注，不会静默降级。
- 本机转发端口只监听 `127.0.0.1`，局域网内其它设备访问不到。
- 开启全局代理时会记录你原来的系统代理设置，关闭开关或退出应用时**原样还原**；
  即使应用被强制结束，下次启动也会先把残留还原掉。
- 本应用与浏览器插件**不共享配置**，两者互不读取对方的数据。

---

## 卸载

1. 关掉全局代理开关（或直接退出，应用会自动还原系统代理）。
2. 删除 `%APPDATA%/proxy-bridge/` 目录，彻底清除配置与凭据。
3. 浏览器插件是独立安装的，需在 `chrome://extensions` 里单独移除。
