# Proxy Bridge

连接你自己那台远程代理服务器的两个客户端：

| | 用途 |
| --- | --- |
| **[Application](Application/)** | Windows 桌面应用，一键让**整台电脑**走代理 |
| **[Plugin](Plugin/)** | Chrome / Edge 扩展，只让**浏览器**走代理 |

两者互不依赖，各自配置、各自工作。用哪个都行，也可以两个都用。

---

## 它解决什么

你有一台带账号密码的代理服务器。想让电脑上的程序用上它，通常要面对四个麻烦：

1. **账号密码要填进每个软件的配置里**，散落各处，改密码得挨个改
2. **系统代理只能填一个本机地址**，没法直接填带认证的远程服务器
3. **所有流量都绕道远程**，访问内网或国内站点反而更慢
4. **明文代理在跨境链路上不稳定**：客户端发出的 `CONNECT 域名:443` 是明文，
   会被中途识别并重置，实测成功率只有 17%~37% 且随时间波动

这个项目把这些问题收进两个客户端里：桌面应用负责整机，浏览器扩展负责浏览器。
第 4 条由桌面应用的**内置 SSH 隧道**解决。

## 快速开始

### 桌面应用（整机代理）

```powershell
cd Application
npm install
npm start
```

1. 填服务器地址、端口、账号密码（**协议保持默认的「自动识别」即可**，不确定时不用管）
2. 点 **测试连接** —— 成功会显示握手耗时和**出口 IP**，用来确认流量确实从代理出去了
3. 打开界面上的**总开关**

开关会自动完成三件事：校验服务器可用 → 启动本机转发端口 → 接管 Windows 系统代理。
关闭开关或退出应用时反向执行，**你原来的系统代理设置会原样还原**。

### 浏览器扩展（只管浏览器）

Chrome / Edge 打开 `chrome://extensions` → 开启**开发者模式** → **加载已解压的扩展程序** → 选 `Plugin/` 目录
→ 在扩展设置页填写同一台服务器的信息 → 打开开关。

扩展自己直连代理服务器，**不需要桌面应用运行**。HTTP/HTTPS 代理的账号密码由扩展自动应答，浏览器不会弹登录框。
开启后扩展会真的探测一次连通性，弹窗顶端直接显示**已连接 / 连不上服务器**以及出口 IP。

### 内置 SSH 隧道（让跨境连接稳定下来）

**为什么需要它**：客户端与代理服务器之间如果直接发明文 `CONNECT`，这个请求在跨境链路上
会被识别并重置。同一时刻、同一服务器的对照实测：

| 方式 | 成功率 |
| --- | --- |
| 明文代理直连 | 4/20（对外站点）／1/5 |
| 放进 SSH 隧道 | **20/20** |

**原理**：SSH 在**本机**就把整条流加密了，中途只能看到一条 SSH 流，看不到代理协议与目标域名。

> 注意：加密必须发生在客户端。把它做在服务器侧是**无效**的——数据离开你电脑时仍是明文，
> 出口那一段照样会被识别。

**它做什么**：在自己的电脑上开一条 SSH 隧道，把「服务器回环地址上的代理端口」映射到本机的
一个回环端口，然后让网关改连这个本地端口。

```
系统代理 → 本机网关(127.0.0.1:7890) → 本机隧道端口 → SSH 加密 → 服务器代理端口 → 目标
```

**怎么开**：高级设置 → 勾选「使用内置 SSH 隧道」→ 填参数 → 点「测试隧道」→ 通过后打开总开关。
测试会验证两件事：隧道能否建立、**对端代理是否真的在服务**（隧道通了不等于代理可用）。

**参数说明**

| 字段 | 说明 |
| --- | --- |
| SSH 用户名 | 通常是 `root` |
| SSH 服务器 | 留空则沿用上面的代理服务器地址（两者常在同一台机器） |
| SSH 端口 | 默认 22 |
| 私钥文件 | 支持 `~`；留空则用 ssh-agent。**对应公钥需已加入服务器的 `authorized_keys`** |
| 对端代理端口 | 服务器上代理监听的端口 |
| 本机隧道端口 | 0 表示自动分配 |

**没有现成密钥？应用可以直接生成**：点「🔑 生成新密钥」，它会在 `~/.ssh/` 下生成一对
ed25519 密钥并把路径自动填好，然后把公钥和一行现成命令显示出来，复制到服务器执行即可：

```bash
echo 'ssh-ed25519 AAAA...' >> /root/.ssh/authorized_keys
```

生成的是 **OpenSSH 原生格式**私钥（`-----BEGIN OPENSSH PRIVATE KEY-----`）。
这一点是必需的：Node 内置的 crypto 只能导出 PKCS#8，而 Windows / macOS 自带的 ssh
客户端拒绝读取该格式（实测报 `invalid format`），所以项目里手工拼了 OpenSSH 的线格式。

**把应用发给别人时**，他需要三样东西：

1. **你的服务器地址、端口、代理账号密码**（填「代理服务器」那一栏）
2. **他自己的密钥对** —— 点应用里的「生成新密钥」即可，不需要装任何 SSH 工具
3. **把他的公钥加到你的服务器上** —— 他点生成后界面会给出那行 `echo ... >>` 命令，
   你（或在服务器上有权限的人）执行一次

也就是说：**私钥永远只在他自己机器上，你不需要也不应该把自己的私钥给他。**
每人一把钥匙，谁不用了就把对应那行从 `authorized_keys` 里删掉。

> 服务器上 `authorized_keys` 里每行末尾的备注（默认 `proxy-bridge`）就是用来区分是谁的，
> 删之前可以先用 `ssh-keygen -lf ~/.ssh/authorized_keys` 看清指纹与归属。

**密钥找不到或不被接受时**：应用会依次尝试配置的密钥和常见位置（`id_ed25519`、
`id_ed25519_proxy`、`id_rsa`、`id_ecdsa`）。全部失败时，错误信息会列出**每把密钥的指纹**，
可以直接和服务器上 `ssh-keygen -lf ~/.ssh/authorized_keys` 的输出对照，一眼看出该用哪把。

**断线自愈**：链路抖动导致 SSH 断开时，应用会自动重连（退避 1.5s→15s），
界面状态条会显示重连次数。

**依赖**：复用系统自带的 OpenSSH 客户端（Windows 10+ / macOS / Linux 均内置），
不引入任何第三方依赖。

## 功能对照

| | 桌面应用 | 浏览器扩展 |
| --- | --- | --- |
| 作用范围 | 整台电脑（系统代理） | 仅浏览器 |
| 怎么开 | 一个总开关 | 一个开关 |
| 协议选择 | **自动识别**，也可手动指定 | 手动指定 |
| 直连例外 | ✓ 可配置 | 浏览器自己的绕过列表 |
| 服务器认证 | ✓ 支持 | ✓ 支持（HTTP/HTTPS 自动应答） |
| 连接状态提示 | 测试连接给出原因 | 弹窗实时显示可否出网 |
| 凭据存储 | Windows DPAPI 加密 | 浏览器扩展存储，可选择不保存 |
| 需要对方运行吗 | 不需要 | 不需要 |

### 桌面应用还能做什么

- **不启动全局代理也能用**：手动把某个程序的代理指向 `127.0.0.1:7890` 即可，
  支持 HTTP 与 SOCKS5 两种协议
- **诊断**：测试连接会给出具体原因（认证失败 / 超时 / 端口被拒），而不是笼统的"连接失败"
- **安全兜底**：开启前先校验服务器，连不上就拒绝开启；退出时自动还原系统代理，
  即使被强制结束，下次启动也会先清理残留

## 已知限制

- **SOCKS5 + 账号密码，在浏览器扩展里无法自动化**：Chromium 不提供向 SOCKS5 代理注入凭据的接口，
  会弹出浏览器原生登录框。桌面应用不受此限制。若要在浏览器里免弹窗，用 HTTP 代理。
- **同一时间只能有一个扩展控制浏览器代理**：装了别的代理类扩展会互相覆盖。
- **企业策略可能锁定系统代理**：被管控的电脑上，应用的全局代理开关可能不生效。

---

## 安全说明

- 仓库内**不包含任何真实的代理服务器地址、端口、账号或密码**，也不预置默认值；
  全部由使用者在运行时填写，只保存在本机。
- 桌面应用的服务器地址、端口、账号与密码都用 Windows DPAPI 加密后写入
  `%APPDATA%\proxy-bridge\config.json`，该文件不在仓库目录内，打开也看不出内容。
- 桌面应用不写任何日志文件：日志会带出服务器地址，所以主进程的输出被整体关闭。
- 桌面应用的本机转发端口只监听 `127.0.0.1`，局域网内其它设备访问不到。
- 浏览器扩展不发起任何对外网络请求，只调用浏览器的代理 API。

## 开发

```powershell
cd Application
npm run dev         # 开发模式：Vite + Electron，界面热更新
npm run typecheck   # 类型检查（主进程 + 界面）
npm test            # 单元测试 + 端到端测试（全部使用本机模拟服务，不联网）
npm run build       # 只构建，不启动
npm run dist        # 打包成 exe（产物在项目根目录的 release/）
```

浏览器扩展是纯原生 JS/HTML/CSS，无依赖、无构建步骤，改完在 `chrome://extensions` 里点一下刷新即可。

### 测试覆盖

`npm test` 会用本机临时服务完整走一遍代理链路，不接触任何外部服务器：

- **直连例外匹配**：域名/通配符/端口限定的各种写法
- **协议自动识别**：mock 只支持某一种协议时能否识别出来，全不通时是否逐个给出原因
- **HTTP 与 SOCKS5 上游转发**：认证注入、认证失败处理
- **字节级时序**：隧道建立瞬间，目标首包与握手应答落在同一个 TCP 段时，不能丢字节也不能串位
- **健康检查端点**：供外部探测应用是否在运行
