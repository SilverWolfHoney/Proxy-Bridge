# Proxy Bridge

连接你自己那台远程代理服务器的两个**互相独立**的客户端：一个桌面应用，一个浏览器插件。

```
Proxy/
├── Application/   Electron 桌面应用：开本机代理端口、可接管系统代理、支持分流
└── Plugin/        Chrome / Edge 扩展：只管浏览器自己的代理设置
```

**两者互不依赖。** 它们各自连接同一台远程代理服务器，配置也各自独立：

```
浏览器插件 ──┐
             ├──► 你的远程代理服务器 ──► 目标网站
本应用     ──┘
```

关掉应用，插件照常工作；不装插件，应用也一样工作。应用里的服务器信息**不会**自动同步给插件——两边是两套独立配置。

## 各自的定位

| | 本应用 | 浏览器插件 |
| --- | --- | --- |
| 作用范围 | 本机所有程序（本机端口 / 系统代理） | 仅浏览器 |
| 典型用途 | curl、Git、其它软件；一键接管系统代理 | 日常上网，随时开关 |
| 分流规则 | ✓ 支持（按域名决定直连还是走代理） | 只有浏览器自己的绕过列表 |
| 连接日志与流量统计 | ✓ | ✗ |
| 凭据存储 | Windows DPAPI 加密 | 浏览器扩展存储（可选择不保存密码） |
| 需要对方运行吗 | 不需要 | 不需要 |

## 快速开始

### 桌面应用

```powershell
cd Application
npm install
npm start
```

打开「代理服务器」页填写服务器信息 → 点「测试连接」（成功会显示**出口 IP**）→ 点「启动网关」。

### 浏览器插件

Chrome / Edge 打开 `chrome://extensions` → 开启**开发者模式** → **加载已解压的扩展程序** → 选 `Plugin/` 目录
→ 在插件设置页填写**同一台服务器**的信息 → 打开插件开关。

应用里的「插件 / 关于」页可以一键生成这份配置文本（**不含密码**），省得手打两遍。

## 已知限制

- **SOCKS5 + 账号密码**：Chromium 不提供向 SOCKS5 代理注入凭据的接口，浏览器会弹出原生登录框。
  HTTP/HTTPS 代理的认证则可以自动完成。详见插件文档。
- 同一时间只能有一个扩展控制浏览器代理。
- 企业策略可能锁定系统代理设置。

## 安全约定

- 仓库内**不包含任何真实的代理服务器地址、端口、账号或密码**，也不预置任何默认值；全部由使用者运行时填写。
- 应用的密码以 Windows DPAPI 加密落盘，配置文件权限限制为当前用户。
- 应用的网关默认只监听 `127.0.0.1`。改成 `0.0.0.0` 等于把代理开放给整个局域网，请勿随意修改。
- 应用的连接日志只保留在内存中（最多 300 条），退出即清空，且从不记录凭据。
- 插件不发起任何对外网络请求，只调用浏览器的代理 API。

## 开发

```powershell
cd Application
npm run dev         # 开发模式：Vite + Electron，界面热更新
npm run typecheck   # 类型检查
npm test            # 单元测试 + 本地网关端到端测试（全部用本机模拟服务，不联网）
```

插件是纯原生 JS/HTML/CSS，无依赖无构建，改完在 `chrome://extensions` 里点一下刷新即可。

应用测试覆盖了分流规则匹配、HTTP/SOCKS5 上游转发、Basic 认证注入、认证失败处理，
以及最容易出错的「隧道建立瞬间目标首包与握手应答同段到达」这类字节级场景。
