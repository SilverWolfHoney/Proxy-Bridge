# Proxy Bridge

把浏览器流量交给远程代理服务器的桌面应用 + 浏览器插件。

```
Proxy/
├── Application/   Electron 桌面应用（持有服务器地址与凭据，开本机代理端口）
└── Plugin/        Chrome / Edge 插件（只把浏览器代理指向本机端口）
```

## 它解决什么问题

直接把代理服务器的账号密码填进浏览器或插件，凭据会散落在浏览器配置里，换服务器还得重新配一遍。

这套组合把凭据收拢到桌面应用一处：

```
浏览器 ─► 插件（只知道 127.0.0.1:7890）─► 桌面应用 ─┬─► 直连目标（内网、网银等）
                                                    └─► 远程代理服务器（附加账号密码）
```

- **凭据只存一份**，用 Windows DPAPI 加密保存在应用里，插件里没有、浏览器配置里也没有。
- **换服务器不用碰插件**，改应用里的配置即可。
- **能做分流**，被规则判定为直连的网站不会绕道远程服务器。
- **有连接日志和流量统计**，每个连接走了哪条路、为什么失败都看得见。

## 快速开始

1. **启动应用**

   ```powershell
   cd Application
   npm install
   npm start
   ```

2. **填写服务器信息** —— 打开「代理服务器」页，填协议、地址、端口、账号密码，点「测试连接」。
   成功后界面会显示**出口 IP**，用它确认流量确实从代理出去了。

3. **启动网关** —— 点右上角「启动网关」，默认监听 `127.0.0.1:7890`。

4. **安装插件** —— Chrome/Edge 打开 `chrome://extensions` → 开启开发者模式 →
   「加载已解压的扩展程序」→ 选 `Plugin/` 目录 → 在插件设置里把端口填成 `7890` → 打开插件开关。

   应用里的「插件 / 关于」页有按钮可以直接打开插件目录并复制路径。

## 安全约定

- 仓库内**不包含任何真实的代理服务器地址、端口、账号或密码**，也不预置任何默认值；全部由使用者运行时填写。
- 密码以 DPAPI 加密形式落盘，配置文件权限限制为当前用户。
- 网关默认只监听 `127.0.0.1`。改成 `0.0.0.0` 等于把代理开放给整个局域网，请勿随意修改。
- 连接日志只保留在内存中（最多 300 条），退出即清空，且从不记录凭据。

## 开发

```powershell
cd Application
npm run dev         # 开发模式：Vite + Electron，界面热更新
npm run typecheck   # 类型检查
npm test            # 单元测试 + 本地网关端到端测试（全部用本机模拟服务，不联网）
```

测试覆盖了分流规则匹配、HTTP/SOCKS5 上游转发、Basic 认证注入、认证失败处理，
以及最容易出错的「隧道建立瞬间目标首包与握手应答同段到达」这类字节级场景。
