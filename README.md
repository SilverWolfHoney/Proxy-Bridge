# Proxy Bridge

连接你自己那台远程代理服务器的两个客户端：

| | 用途 |
| --- | --- |
| **[Application](Application/)** | Windows 桌面应用，一键让**整台电脑**走代理 |
| **[Plugin](Plugin/)** | Chrome / Edge 扩展，只让**浏览器**走代理 |

两者互不依赖，各自配置、各自工作。用哪个都行，也可以两个都用。

---

## 它解决什么

你有一台带账号密码的代理服务器。想让电脑上的程序用上它，通常要面对三个麻烦：

1. **账号密码要填进每个软件的配置里**，散落各处，改密码得挨个改
2. **系统代理只能填一个本机地址**，没法直接填带认证的远程服务器
3. **所有流量都绕道远程**，访问内网或国内站点反而更慢

这个项目把这些问题收进两个客户端里：桌面应用负责整机，浏览器扩展负责浏览器。

## 快速开始

### 桌面应用（整机代理）

```powershell
cd Application
npm install
npm start
```

1. 填服务器地址、端口、账号密码（**协议保持默认的「自动识别」即可**，不确定时不用管）
2. 点 **测试连接** —— 成功会显示握手耗时和**出口 IP**，用来确认流量确实从代理出去了
3. 打开界面上的**总开关**

开关会自动完成三件事：校验服务器可用 → 启动本机转发端口 → 接管 Windows 系统代理。
关闭开关或退出应用时反向执行，**你原来的系统代理设置会原样还原**。

### 浏览器扩展（只管浏览器）

Chrome / Edge 打开 `chrome://extensions` → 开启**开发者模式** → **加载已解压的扩展程序** → 选 `Plugin/` 目录
→ 在扩展设置页填写同一台服务器的信息 → 打开开关。

扩展自己直连代理服务器，**不需要桌面应用运行**。HTTP/HTTPS 代理的账号密码由扩展自动应答，浏览器不会弹登录框。
开启后扩展会真的探测一次连通性，弹窗顶端直接显示**已连接 / 连不上服务器**以及出口 IP。

## 功能对照

| | 桌面应用 | 浏览器扩展 |
| --- | --- | --- |
| 作用范围 | 整台电脑（系统代理） | 仅浏览器 |
| 怎么开 | 一个总开关 | 一个开关 |
| 协议选择 | **自动识别**，也可手动指定 | 手动指定 |
| 直连例外 | ✓ 可配置 | 浏览器自己的绕过列表 |
| 服务器认证 | ✓ 支持 | ✓ 支持（HTTP/HTTPS 自动应答） |
| 连接状态提示 | 测试连接给出原因 | 弹窗实时显示可否出网 |
| 凭据存储 | Windows DPAPI 加密 | 浏览器扩展存储，可选择不保存 |
| 需要对方运行吗 | 不需要 | 不需要 |

### 桌面应用还能做什么

- **不启动全局代理也能用**：手动把某个程序的代理指向 `127.0.0.1:7890` 即可，
  支持 HTTP 与 SOCKS5 两种协议
- **诊断**：测试连接会给出具体原因（认证失败 / 超时 / 端口被拒），而不是笼统的"连接失败"
- **安全兜底**：开启前先校验服务器，连不上就拒绝开启；退出时自动还原系统代理，
  即使被强制结束，下次启动也会先清理残留

## 已知限制

- **SOCKS5 + 账号密码，在浏览器扩展里无法自动化**：Chromium 不提供向 SOCKS5 代理注入凭据的接口，
  会弹出浏览器原生登录框。桌面应用不受此限制。若要在浏览器里免弹窗，用 HTTP 代理。
- **同一时间只能有一个扩展控制浏览器代理**：装了别的代理类扩展会互相覆盖。
- **企业策略可能锁定系统代理**：被管控的电脑上，应用的全局代理开关可能不生效。

---

## 安全说明

- 仓库内**不包含任何真实的代理服务器地址、端口、账号或密码**，也不预置默认值；
  全部由使用者在运行时填写，只保存在本机。
- 桌面应用的服务器地址、端口、账号与密码都用 Windows DPAPI 加密后写入
  `%APPDATA%\proxy-bridge\config.json`，该文件不在仓库目录内，打开也看不出内容。
- 桌面应用不写任何日志文件：日志会带出服务器地址，所以主进程的输出被整体关闭。
- 桌面应用的本机转发端口只监听 `127.0.0.1`，局域网内其它设备访问不到。
- 浏览器扩展不发起任何对外网络请求，只调用浏览器的代理 API。

## 开发

```powershell
cd Application
npm run dev         # 开发模式：Vite + Electron，界面热更新
npm run typecheck   # 类型检查（主进程 + 界面）
npm test            # 单元测试 + 端到端测试（全部使用本机模拟服务，不联网）
npm run build       # 只构建，不启动
npm run dist        # 打包成 exe（产物在项目根目录的 release/）
```

浏览器扩展是纯原生 JS/HTML/CSS，无依赖、无构建步骤，改完在 `chrome://extensions` 里点一下刷新即可。

### 测试覆盖

`npm test` 会用本机临时服务完整走一遍代理链路，不接触任何外部服务器：

- **直连例外匹配**：域名/通配符/端口限定的各种写法
- **协议自动识别**：mock 只支持某一种协议时能否识别出来，全不通时是否逐个给出原因
- **HTTP 与 SOCKS5 上游转发**：认证注入、认证失败处理
- **字节级时序**：隧道建立瞬间，目标首包与握手应答落在同一个 TCP 段时，不能丢字节也不能串位
- **健康检查端点**：供外部探测应用是否在运行
